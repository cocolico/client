# 远端模型与本地重定向的连续轨迹对比

当前默认页面左侧为远端原始 `prediction.npz/keypoints`，右侧为 `retarget.npz` 中Wuji关节角和手根位姿经FK重建的21点。
两侧按相同预测帧、客户端执行时间轴同步播放整次运行，使用共同的显示比例。真机编码器反馈不参与默认页面的误差计算。
逐指显示原始/重定向弯折角、弯折差、原始指尖位置差，以及对骨长适配目标的拟合残差。原始位置差包含骨长差异，不应直接解释为求解失败。
模型未直接输出独立手根姿态，因此腕点位置差与骨架姿态用于比较根部效果，不宣称独立测得模型的六维手根误差。
`/live` 仍保留原模型/目标/真机实时页，以下部分描述也保留了原真机反馈录像与采样方式。

## 整段连续轨迹回放（当前默认页面）

默认页面已改成整次运行的一条连续轨迹，自动串联所有已记录轮次并从头播放，不需要逐轮选择。支持慢放、2/4倍快放、暂停、循环和全程进度拖动；跨32步轮次交界时不重置播放。
模型全部预测点、重定向目标和真机FK反馈按已发送步号对齐；绘制整段指尖及腕点路径，显示首末姿态和逐指弯折趋势。
可切换固定空间视角/相机投影，并消除腕点平移以专看手指。当前回放使用采样到的编码器轨迹，不伪造未采到的中间真实姿态。

客户端运行期间打开 `http://127.0.0.1:8765/`（端口占用以终端为准），原实时页面保留在 `/live`。
客户端停止后，可独立读取已有记录，无须启动机器人：

```bash
./python trajectory_replay.py --port 8766
```

浏览器打开 `http://127.0.0.1:8766/`。通过 `--session runs/具体运行目录` 可固定查看某次运行。
最后一轮若被中断会标记不完整。合并多轮时相机投影背景使用首轮观测图，真实相机对比录像另见 `monitor/comparison.avi`。

`config.rb_tidying.json` 已启用监视器，使用原命令启动即可：

```bash
cd '/media/descfly/新加卷/ty/replay/client/aubo_wuji'
./run --config config.rb_tidying.json run --steps 32 --iterations 1000000 --execute
```

同机浏览器打开 `http://127.0.0.1:8765`。如果端口占用，终端 `LIVE COMPARISON` 和本次运行的 `monitor_url.txt` 会显示实际地址。仅监听本机回环地址，不开放远程访问。第一个目标成功发送后显示实时对比。

- 左侧背景：本轮模型输入图；蓝色：原始模型21点和整段腕点轨迹；橙色：当前成功发送的双臂/双手目标，经FK重建的21点。
- 右侧背景：实时相机图；绿色：实测关节经FK重建的21点及最近150次采样的腕点轨迹；橙色：当前目标。
- 下方：每根手指的原始预测/目标/实际几何弯折角、最大电机关节误差、指尖空间误差，以及手部空间骨架视图。
- 步号由执行器在控制命令成功返回后发布；模型与目标不是按独立动画时钟播放。臂手读取非硬件同步，页面标注相机延迟、命令年龄和读取跨度。默认约5FPS，因此不保证捕获每个瞬间。

## 判断问题所在

1. 蓝色模型手指没有收拢：先检查模型预测与视觉/任务条件。
2. 蓝色有收拢，但橙色目标没有，或方向相反：检查21点重定向、骨长适配、左右手/关节顺序。
3. 橙色目标收拢，绿色实际不跟随且关节误差持续偏大：检查硬件执行、控制模式、关节映射、限位或接触阻挡。
4. 绿色能跟随橙色，但抓取仍失败：需要结合真实画面检查抓取位置、时机、物体接触及夹持力；关节跟踪良好不等于已经抓住物体。

弯折角是骨段夹角的绝对值，不是关节电机角，也不能独自判断正反弯方向。绿色骨架由编码器和标定FK得到，不是独立视觉测量，无法独立排除标定/机械模型错误。若相机中的实体手指与绿色骨架持续错位，应先检查标定与映射。

本次运行自动保存：

```text
runs/<本次运行>/monitor_url.txt
runs/<本次运行>/monitor/comparison.avi
runs/<本次运行>/monitor/feedback.jsonl
```

AVI为约5FPS左右对比录像（采样慢时播放时间可能不同于实际时间）；JSONL保存实际时间戳、原始预测/命令FK/实测FK、关节误差和延迟，可供复查。Ctrl+C正常退出会封装录像。强制断电或kill可能使末尾录像不完整。

监视器不重新打开相机流，不发布手部目标，不调用机械臂运动接口；使用现有相机缓冲和独立的只读Aubo连接。绘图、HTTP和录像在监视线程；执行线程只复制当前52维目标与步号。监视器故障不会更改控制目标，但仍可能增加本机CPU负载。

关闭监视器可将此配置中的 `monitor.enabled` 设为 `false`。本功能测试使用模拟相机和编码器数据，未自动启动真机运动验证。
